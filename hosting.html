Hosting#

A catalog channel is plain files, so any host works. The app needs one URL: the manifest's. Blob, asset and preview URLs are resolved from the manifest.

Host Source in the app Build with
GitHub release GitHubReleaseSource(owner, repo) (latest) or with tag livery build … --github owner/repo --tag T
Static host, GitHub Pages, S3, CDN StaticSource("https://host/catalog/main") livery build … (static layout)
Design server channel StaticSource("https://server/v1/catalogs/acme/channels/main") its upload API
App assets (fallback) TemplateRepository.Bundled(manifest, read) livery build …, copied into assets

GitHub releases#

livery build catalog build/release --github acme/app-templates --tag catalog-12 --key acme.key --key-id acme-1
gh release create catalog-12 build/release/* --repo acme/app-templates
  • Assets are flat (<sha>.rc, <sha>.png); the manifest points blobBase at the release's download URL.
  • GitHubReleaseSource(owner, repo) follows releases/latest, so keep catalog releases in their own repository.
  • No CORS headers: fine for apps, not for browsers.

From CI, on every merge to main: use Livery's reusable publish workflow, with its review workflow on pull requests (see Repository mode):

jobs:
  publish:
    uses: yschimke/livery/.github/workflows/catalog-publish.yml@v0.3.0
    with: { source: catalog, livery-version: 0.3.0, key-id: acme-1 }
    secrets: { signing-key: '${{ secrets.LIVERY_SIGNING_KEY }}' }
    permissions: { contents: write }

--inspect decodes every .rc and refuses one that reads or emits anything its sidecar doesn't declare, or reads a value as a different type than its contract declares. Use it whenever documents come from more than one tool, or from an agent.

--a2ui <catalogId> also writes a2ui-catalog.json: the catalog's contracts as A2UI components (one per contract major, at its newest minor), the same schema an app's livery-a2ui-compose advertises, for prompting an agent that answers in A2UI.

Checking a change#

livery check compares a catalog source tree with an earlier version of itself: a git revision of its repository, or another tree. Run it on every pull request:

livery check catalog --against origin/main --inspect

It exits 1 when a contract changes in a way apps already installed would break (see Concepts), or when the tree doesn't build. It also lists, for review, every template added, removed or changed: what it now reads and emits, the contract minor it requires (apps on an older minor stop getting it), its size, and which values only the template's own default covers when data leaves them out. It fails while example data the base had is neither current nor kept (livery keep-examples; see Repository mode). A template that starts using a risky feature (a shader, haptics, sound, particles) is noted for review, since it plays only for apps that allow it; --deny-new-features fails the check instead, for a catalog that admits none. --markdown prints it for a pull request comment: a verdict first, then only what needs a decision, summed up per design; --json prints the same report for other tools; agents get it from the MCP server's check_compatibility. livery review prints the markdown with pictures: each changed design drawn with its contract's examples, before and after (see Repository mode).

The serial defaults to the build time in milliseconds, which only grows. If you pass --serial yourself, never let it go down for a channel: apps refuse a lower one as a rollback.

Static hosts and CDNs#

livery build catalog public/catalog/main --key acme.key --key-id acme-1

Upload public/catalog/main/ as is. Serve manifest.json and manifest.sig.json with revalidation (Cache-Control: no-cache and an ETag); everything else is immutable (max-age=31536000, immutable). Browsers need Access-Control-Allow-Origin on all of it.

Channels#

A channel is a whole catalog under its own URL: …/main, …/staging, …/pr-123. Point development builds or a hidden settings switch at a non-main channel to try a change before it ships. Apps cache each source separately, so switching back is clean. Set "channel" in catalog.json, or keep one source tree and publish it to several URLs.

Bundled fallback#

Ship an initial catalog inside the app, so a first launch with no network still draws. On Android, the Gradle plugin builds the catalog's source tree into the APK's assets on every build. It applies the same checks as livery build --inspect, and it is reproducible:

plugins { id("ee.schimke.composeai.livery.catalog") version "<version>" }

livery {
  source.set(layout.projectDirectory.dir("livery"))   // catalog.json, contracts/, designs/
  assetsPath.set("livery")                            // the default
}

When the designs are Kotlin, livery { capture { mainClass.set(…) } } captures them at build time and the catalog built into the assets is that capture, so no .rc is committed (see Authoring).

val repository = TemplateRepository(
  source, KtorFetcher(), JavaCrypto, trust, blobs, kv, clock, targets,
  bundled = AndroidBundled.fromAssets(context),       // null if the app ships none
)

The bundled catalog is trusted as the APK is: it isn't signature-checked and never expires. Anything the repository downloads replaces it. A remote source is optional: an app can start with only the baked catalog and add hosting later. Elsewhere, write a livery build output into the app's resources and pass a TemplateRepository.Bundled(manifest, read).
